AI Simulation Focus Group
Phase 8 이후 개발 계획 및 프로젝트 목표

작성 목적
========
현재 Phase 7까지 구현된 AI 시뮬레이션 서비스의 다음 개발 방향을 정리한다.
Phase 8부터는 관리자 기능, 키워드 기반 인사이트, AI 운영 안정화, 테스트와 배포를 순서대로 진행한다.


현재 프로젝트 상태
==================
- Multi-Agent 기반 상품 분석 파이프라인 구현
- Product Analysis, Persona, Consumer Response, Moderator, Discussion 구현
- React 기반 입력 및 결과 화면 구현
- SQLite + SQLAlchemy + Alembic 저장 구조 구현
- 시뮬레이션 이력·상세·비교 기능 구현
- 회원가입·로그인·JWT 인증 구현
- 사용자별 시뮬레이션 데이터 분리 구현
- Google OAuth 연동 코드 구현
- 프론트엔드 production build 성공
- 백엔드 Python 컴파일 성공

Phase 7.5 - 인증 보완
=====================
Phase 8을 시작하기 전에 인증 기능을 운영 가능한 수준으로 보완한다.

백엔드
------
- /simulations/{id}/personas 소유권 검사 추가
- /simulations/{id}/report 소유권 검사 추가
- /simulations/{id}/discussion 소유권 검사 추가
- /simulate 테스트용 API의 운영 정책 정리
- 로그인하지 않은 사용자의 저장·조회 요청 차단
- 사용자별 401 Unauthorized 처리
- 다른 사용자 데이터 접근 시 403 또는 404 처리 정책 확정
- 사용자 삭제 정책 확정
  - 관련 데이터 함께 삭제
  - 또는 사용자 비활성화 후 데이터 보존
- Google Cloud OAuth Client ID와 Secret 설정
- Google OAuth Redirect URI 실제 테스트
- Google 계정 자동 회원가입 및 기존 계정 연결 테스트

보안
----
- JWT Secret을 반드시 환경변수로 관리
- 개발용 기본 Secret 제거
- localStorage JWT 사용 여부 재검토
- 운영 환경에서는 HttpOnly Secure Cookie 또는 Refresh Token 구조 검토
- API Key, 비밀번호, JWT가 로그에 노출되지 않도록 처리

완료 기준
--------
- 로그인한 사용자는 자신의 시뮬레이션만 조회 가능
- 다른 사용자 시뮬레이션 접근 차단
- 인증이 필요한 API에 토큰이 없으면 401 반환
- Google 로그인 성공 후 서비스 화면으로 이동


Phase 8 - 관리자 메뉴와 RBAC
============================
관리자 기능을 추가한다. 관리자 권한은 프론트엔드가 아니라 백엔드에서 검증한다.

권한
----
- USER
- ADMIN

백엔드 권한 구조
----------------
- get_current_user dependency 사용
- require_admin dependency 추가
- 관리자 API마다 require_admin 적용
- 일반 사용자의 관리자 API 접근 시 403 반환
- 프론트 메뉴 숨김은 UX 처리일 뿐 보안 수단으로 사용하지 않음

관리자 API
----------
- GET /admin/dashboard
- GET /admin/users
- PATCH /admin/users/{user_id}/role
- GET /admin/simulations
- DELETE 또는 PATCH /admin/simulations/{simulation_id}
- GET /admin/ai-logs
- GET /admin/keywords
- POST /admin/keywords
- PATCH /admin/keywords/{keyword_id}
- DELETE /admin/keywords/{keyword_id}

관리자 대시보드 데이터
----------------------
- 전체 사용자 수
- 전체 시뮬레이션 수
- 오늘 실행된 시뮬레이션 수
- 성공·실패·진행 중 수
- 평균 구매의도 점수
- 최근 시뮬레이션 목록
- 사용자별 실행 수
- AI 사용량과 예상 비용
- 문제가 있는 시뮬레이션 목록

프론트엔드
----------
- 관리자 여부에 따른 관리자 메뉴 표시
- 관리자 대시보드 화면
- 사용자 목록과 역할 변경
- 전체 시뮬레이션 목록
- 문제 있는 시뮬레이션 확인
- AI 사용량 로그 화면
- 키워드 사전 관리 화면
- 401·403·404 상태 처리

완료 기준
--------
- ADMIN 계정만 관리자 API 호출 가능
- USER 계정은 관리자 API에서 403 반환
- 관리자 화면이 실제 DB 데이터를 표시
- 역할 변경 결과가 다음 요청부터 적용


Phase 9 - 키워드 및 인사이트 연결
==================================
상품 설명과 광고 문구에서 핵심 키워드를 추출하고 AI 결과와 연결한다.

구현 순서
---------
1. 상품 설명·광고 문구에서 키워드 추출
2. 키워드 정규화 및 중복 제거
3. keywords 테이블 저장
4. simulation_keywords 연결
5. 키워드별 긍정·부정 반응 집계
6. 키워드별 구매의도 점수 연결
7. Persona별 키워드 민감도 분석
8. Moderator·Discussion 결과와 키워드 연결
9. 관리자 키워드 사전 관리

키워드 분석 예시
----------------
- 가격 관련 키워드가 구매 장벽을 높이는가?
- 어떤 키워드가 긍정 반응을 만드는가?
- 어떤 Persona가 특정 키워드에 민감한가?
- 특정 키워드를 광고 문구에서 수정하면 결과가 좋아지는가?

프론트엔드
----------
- 주요 키워드 목록
- 키워드별 긍정·부정 반응
- 키워드별 구매의도 점수
- Persona별 키워드 반응
- 키워드 수정 전·후 비교
- 키워드 인사이트 요약

완료 기준
--------
- 생성된 시뮬레이션에 키워드가 저장됨
- 키워드와 Persona·반응·구매의도가 연결됨
- 관리자 화면에서 키워드 사전 관리 가능


Phase 10 - AI 운영 안정화
==========================
AI 결과를 단순 출력하는 수준에서 운영 가능한 구조로 개선한다.

AI 응답 안정성
--------------
- 모든 AI 응답 Pydantic 검증
- JSON 형식 오류 처리
- 필수 필드 누락 처리
- 잘못된 점수 범위 처리
- Agent별 재시도
- 전체 요청 timeout
- Agent별 timeout
- 실패한 Agent의 오류 메시지 저장
- 전체 시뮬레이션 실패 상태 저장
- 실패한 시뮬레이션 재실행 기능

사용량 및 비용 기록
-------------------
- 모델명 기록
- Agent명 기록
- 입력 token 기록
- 출력 token 기록
- 전체 token 기록
- 실행 시간 기록
- 예상 비용 계산
- simulation_id 연결
- AIUsageLog 테이블 저장

권장 AI 호출 흐름
-----------------
AI 호출 시작
  -> 시작 시간 기록
  -> 모델·Agent 기록
  -> 요청 실행
  -> 응답 JSON 검증
  -> token·비용 계산
  -> 실행 시간 기록
  -> 성공 또는 실패 로그 저장

개인정보 및 보안
-----------------
- API Key 로그 출력 금지
- 사용자 비밀번호 로그 출력 금지
- JWT 로그 출력 금지
- 민감한 사용자 입력 원본 로그 저장 주의
- 운영 환경에서는 AI 원본 응답 보존 범위 결정

완료 기준
--------
- AI 오류가 발생해도 서버가 비정상 종료되지 않음
- 실패 시뮬레이션이 failed 상태로 저장됨
- Agent별 사용량·비용·실행 시간이 조회됨
- 재시도와 timeout이 동작함

최종 프로젝트 목표
==================
AI Simulation Focus Group은 상품명, 상품 설명, 타깃 고객, 광고 문구를 입력하면 AI 기반 가상 소비자 패널이 제품을 평가하고, 실제 사용자와 관리자가 그 결과를 지속적으로 조회·비교·관리할 수 있는 서비스이다.

사용자 관점
-----------
- 회원가입 또는 Google 로그인
- 상품 정보와 광고 문구 입력
- AI 시뮬레이션 실행
- Executive Summary 확인
- 상품 분석 확인
- Persona별 반응 확인
- 그룹 Discussion 확인
- 구매의도 점수 확인
- 개선 우선순위 확인
- 과거 시뮬레이션 조회
- 여러 결과 비교
- 자신의 데이터만 관리

관리자 관점
-----------
- 전체 사용자 관리
- 사용자 역할 관리
- 전체 시뮬레이션 관리
- 성공·실패 통계 확인
- AI 사용량·비용 확인
- 오류가 있는 시뮬레이션 확인
- 키워드 사전 관리
- 운영 데이터 기반 인사이트 확인

기술 목표
---------
- React + TypeScript 프론트엔드
- FastAPI 백엔드
- SQLAlchemy ORM
- Alembic 마이그레이션
- SQLite 개발 환경
- PostgreSQL 배포 환경
- JWT 인증
- RBAC 관리자 권한
- Multi-Agent AI pipeline
- Pydantic 응답 검증
- JSON 기반 AI 결과 저장
- AI 사용량 및 비용 추적
- Docker 기반 실행
- 자동 테스트와 배포 가능한 구조

최종 사용자 흐름
----------------
1. 회원가입 또는 로그인
2. 상품명·상품 설명·타깃 고객·광고 문구 입력
3. AI 시뮬레이션 실행
4. 상품 분석과 Executive Summary 확인
5. Persona 반응 확인
6. 구매의도와 주요 장벽 확인
7. Discussion 결과 확인
8. 결과 DB 저장
9. 이력 화면에서 과거 결과 조회
10. 여러 시뮬레이션 비교
11. 키워드 기반 인사이트 확인
12. 관리자는 운영 대시보드에서 전체 데이터 관리

개발 원칙
=========
- 기존 Product Analysis·Persona·Response·Moderator·Discussion 기능을 유지한다.
- API·DB·Frontend 스키마를 함께 변경한다.
- 모든 권한은 백엔드에서 검증한다.
- AI 응답은 항상 검증 후 저장한다.
- 단계별 구현 후 서버·API·Frontend build를 검증한다.
- 비밀번호·API Key·JWT·개인정보를 로그에 남기지 않는다.
- 기능을 추가하기 전에 데이터 흐름과 저장 구조를 먼저 정의한다.
- 각 Phase 종료 시 실제 사용 흐름으로 검증한다.
